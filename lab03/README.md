## 2. Соединение трёх таблиц: INNER JOIN

**Задание 1.** Получить каталог товаров с названиями категорий и магазинов вместо одних идентификаторов.

```sql
SELECT
    p.id,
    p.title,
    c.name category,
    s.store_name seller,
    p.price
FROM products p
INNER JOIN categories c ON c.id = p.category_id
INNER JOIN sellers s ON s.id = p.seller_id
ORDER BY p.id;
```

Первое соединение находит категорию по `products.category_id`, второе — магазин по `products.seller_id`. INNER JOIN оставляет только строки с найденными соответствиями. У всех тестовых товаров категория и продавец существуют.

**Результат: 1000 строк.**

| 1 | Телефон №1 | Телефоны | Магазин 1 | 17698.34 |
| 2 | Телефон №2 | Телефоны | Магазин 1 | 36086.35 |
| 3 | Телефон №3 | Телефоны | Магазин 1 | 11405.92 |
| 4 | Телефон №4 | Телефоны | Магазин 1 | 1002.37 |

## 3. Товары без отзывов: LEFT JOIN

**Задание 2.** Найти товары без соответствующих записей в таблице отзывов.

```sql
SELECT
    p.id,
    p.title,
    r.score,
    r.comment,
    p.price
FROM products p
LEFT JOIN reviews r ON r.product_id = p.id
WHERE r.id IS NULL
ORDER BY p.id;
```

LEFT JOIN сохраняет товары без отзывов и подставляет NULL в поля правой таблицы. `WHERE r.id IS NULL` оставляет только такие строки. Проверяется ключ отзыва, а не `r.comment`: у существующего отзыва текст тоже может отсутствовать.

Такой приём называют **антисоединением** `LEFT ANTI JOIN`.

**Результат: 999 строк.** Отзывы в тестовом наборе есть только у товара №1.

| id | title | score | comment | price |
|---:|---|---|---|---:|

| 3 | Телефон №3 | NULL | NULL | 11405.92 |
| 4 | Телефон №4 | NULL | NULL | 1002.37 |
| 5 | Телефон №5 | NULL | NULL | 4697.10 |

## 4. Количество товаров и средняя цена: GROUP BY

**Задание 3.** Рассчитать статистику по каждой категории, включая категории без товаров.

```sql
SELECT
    c.id,
    c.name category,
    COUNT(p.id) products_count,
    AVG(p.price) avg_price
FROM categories c
LEFT JOIN products p ON p.category_id = c.id
GROUP BY c.id, c.name
ORDER BY c.id;
```

- GROUP BY формирует группы по категориям.
- `COUNT(p.id)` считает найденные товары, игнорируя NULL.
- `AVG(p.price)` вычисляет среднюю цену товаров категории.
- LEFT JOIN сохраняет категории без товаров: количество будет 0, средняя цена — NULL.

`COUNT(*)` здесь не подходит: у пустой категории он посчитал бы одну строку, созданную внешним соединением.

**Результат: 5 строк.**

| id | category | products_count | avg_price, ≈ |
|---:|---|---:|---:|
| 1 | Электроника | 0 | NULL |
| 2 | Книги | 0 | NULL |
| 3 | Одежда | 0 | NULL |
| 4 | Телефоны | 500 | 24969.84 |
| 5 | Ноутбуки | 500 | 54057.39 |

В «Электронике» 0 товаров, поскольку запрос считает только прямые привязки. Товары дочерних категорий автоматически не включаются в родительскую.

## 5. Фильтрация групп: HAVING

**Задание 4.** Выбрать категории, в которых средняя цена активных товаров превышает 30000 руб.

```sql
SELECT
    c.id,
    c.name category,
    COUNT(p.id) products_count,
    AVG(p.price) avg_price
FROM categories c
INNER JOIN products p ON p.category_id = c.id
WHERE p.is_active = TRUE
GROUP BY c.id, c.name
HAVING AVG(p.price) > 30000
ORDER BY avg_price DESC, c.id;
```

WHERE отбирает активные товары **до группировки**. HAVING фильтрует категории **после расчёта среднего**. Поэтому средние цены здесь отличаются от предыдущего запроса, где учитывались и неактивные товары.

**Результат: 1 строка.**

| id | category | products_count | avg_price, ≈ |
|---:|---|---:|---:|
| 5 | Ноутбуки | 450 | 54632.32 |

## 6. Подзапросы

**Задание 5.** Использовать скалярный подзапрос, IN и EXISTS.

### 6.1. Скалярный подзапрос

Выбрать товары дороже средней цены по всему каталогу.

```sql
SELECT
    p.id,
    p.title,
    p.price
FROM products p
WHERE p.price > (
    SELECT AVG(price)
    FROM products
)
ORDER BY p.price DESC, p.id;
```

Вложенный запрос возвращает одно значение — среднюю цену `39513.6181`. Внешний сравнивает с ней цену каждого товара. Подзапрос не ссылается на внешний запрос, поэтому он некоррелированный.

**Результат: 439 строк.**

| id | title | price |
|---:|---|---:|
| 935 | Ноутбук №435 | 99857.04 |
| 533 | Ноутбук №33 | 99836.94 |
| 640 | Ноутбук №140 | 99775.40 |
| 514 | Ноутбук №14 | 99678.43 |
| 949 | Ноутбук №449 | 99410.34 |

### 6.2. Подзапрос с IN

Выбрать товары в дочерних категориях.

```sql
SELECT
    p.id,
    p.title,
    p.category_id,
    p.price
FROM products p
WHERE p.category_id IN (
    SELECT c.id
    FROM categories c
    WHERE c.parent_id IS NOT NULL
)
ORDER BY p.id;
```

Подзапрос возвращает номера категорий с родителем. IN проверяет, входит ли категория товара в полученное множество. В текущем наборе все товары относятся к дочерним категориям «Телефоны» и «Ноутбуки».

**Результат: 1000 строк.**

| id | title | category_id | price |
|---:|---|---:|---:|
| 1 | Телефон №1 | 4 | 17698.34 |
| 2 | Телефон №2 | 4 | 36086.35 |
| 3 | Телефон №3 | 4 | 11405.92 |
| 4 | Телефон №4 | 4 | 1002.37 |
| 5 | Телефон №5 | 4 | 4697.10 |

### 6.3. Коррелированный подзапрос с EXISTS

Выбрать магазины, у которых есть хотя бы один товар.

```sql
SELECT
    s.id,
    s.store_name
FROM sellers s
WHERE EXISTS (
    SELECT 1
    FROM products p
    WHERE p.seller_id = s.id
)
ORDER BY s.id;
```

EXISTS проверяет наличие хотя бы одной строки. Подзапрос коррелированный: использует `s.id` текущего магазина из внешнего запроса. `SELECT 1` не считает товары и не ограничивает результат одной строкой — значение в списке выборки для этой проверки несущественно.

**Результат: 2 строки.** Магазины 3–10 существуют, но пока не имеют товаров.

| id | store_name |
|---:|---|
| 1 | Магазин 1 |
| 2 | Магазин 2 |

## 7. Обычный и рекурсивный CTE

**Задание 6.** Разбить запрос на шаги через WITH и обойти иерархию категорий через WITH RECURSIVE.

### 7.1. Статистика активных товаров магазинов

```sql
WITH seller_product_stats AS (
    SELECT
        p.seller_id,
        COUNT(p.id) products_count,
        AVG(p.price) avg_price
    FROM products p
    WHERE p.is_active = TRUE
    GROUP BY p.seller_id
)
SELECT
    s.id,
    s.store_name,
    stats.products_count,
    stats.avg_price
FROM sellers s
INNER JOIN seller_product_stats stats ON stats.seller_id = s.id
WHERE stats.products_count > 100
ORDER BY stats.products_count DESC, s.id;
```

CTE `seller_product_stats` именует результат первого шага — статистику активных товаров по продавцам. Основной запрос добавляет названия магазинов и оставляет магазины с более чем 100 активными товарами. Это имя доступно только в пределах данной SQL-команды.

**Результат: 2 строки.**

| id | store_name | products_count | avg_price, ≈ |
|---:|---|---:|---:|
| 1 | Магазин 1 | 450 | 24974.74 |
| 2 | Магазин 2 | 450 | 54632.32 |

### 7.2. Дерево категории «Электроника»

```sql
WITH RECURSIVE category_tree AS (
    SELECT
        c.id,
        c.parent_id,
        c.name,
        0 depth
    FROM categories c
    WHERE c.name = 'Электроника'

    UNION ALL

    SELECT
        c.id,
        c.parent_id,
        c.name,
        tree.depth + 1
    FROM categories c
    INNER JOIN category_tree tree ON c.parent_id = tree.id
)
SELECT id, parent_id, name, depth
FROM category_tree
ORDER BY depth, id;
```

Начальная часть находит «Электронику» с глубиной 0. Рекурсивная часть ищет детей категорий предыдущего шага и увеличивает глубину на 1. UNION ALL объединяет строки, не устраняя повторения. Обход продолжается, пока очередной шаг не перестанет возвращать строки. Запрос рассчитан на дерево без циклов. 

**Результат: 3 строки.**

| id | parent_id | name | depth |
|---:|---:|---|---:|
| 1 | NULL | Электроника | 0 |
| 4 | 1 | Телефоны | 1 |
| 5 | 1 | Ноутбуки | 1 |

## 8. Представления VIEW

**Задание 7.** Создать не менее двух представлений и продемонстрировать обращения к ним.

Обычный VIEW сохраняет в базе определение запроса, а не копию данных. При последующих обращениях возвращаются актуальные данные в рамках видимости текущей транзакции. В отличие от CTE, представление доступно и в других SQL-командах.

`CREATE OR REPLACE VIEW` позволяет повторно выполнить файл и обновить совместимое определение. Сортировка задаётся при обращении к представлению.

### 8.1. Каталог товаров

```sql
CREATE OR REPLACE VIEW product_catalog AS
SELECT
    p.id product_id,
    p.title,
    c.name category,
    s.store_name seller,
    p.price
FROM products p
INNER JOIN categories c ON c.id = p.category_id
INNER JOIN sellers s ON s.id = p.seller_id;
```

Обращение к представлению:

```sql
SELECT product_id, title, category, seller, price
FROM product_catalog
ORDER BY product_id
LIMIT 10;
```

**Результат обращения: 10 строк** из каталога, содержащего 1000 товаров.

| product_id | title | category | seller | price |
|---:|---|---|---|---:|
| 1 | Телефон №1 | Телефоны | Магазин 1 | 17698.34 |
| 2 | Телефон №2 | Телефоны | Магазин 1 | 36086.35 |
| 3 | Телефон №3 | Телефоны | Магазин 1 | 11405.92 |
| 4 | Телефон №4 | Телефоны | Магазин 1 | 1002.37 |
| 5 | Телефон №5 | Телефоны | Магазин 1 | 4697.10 |

### 8.2. Статистика категорий

```sql
CREATE OR REPLACE VIEW category_product_stats AS
SELECT
    c.id category_id,
    c.name category,
    COUNT(p.id) products_count,
    AVG(p.price) avg_price
FROM categories c
LEFT JOIN products p ON p.category_id = c.id
GROUP BY c.id, c.name;
```

Обращение к представлению:

```sql
SELECT category_id, category, products_count, avg_price
FROM category_product_stats
ORDER BY category_id;
```

| 4 | Телефоны | 500 | 24969.84 |
